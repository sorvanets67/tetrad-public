# vibenotes

Эта папка `tetrad-public` — самостоятельная чистая копия для будущего GitHub-репозитория. Старая история Git, локальные файлы размещения и пользовательские резервные копии в неё не входят. Публикация выполняется только вручную; подготовка папки ничего не отправляет на GitHub.

Личное приложение для конспектов с графическим планшетом. Русский интерфейс, фиксированные страницы 1100×1550, перо с нажимом, маркер, ластик целых штрихов, фото, текст, перемещение и масштабирование, история действий, экспорт PNG и резервная копия JSON.

## Запуск на Linux

Никаких npm-зависимостей и сборки. Открой эту папку в VS Code. Из терминала проекта:

```bash
python3 serve.py
```

Постоянный адрес приложения: **http://127.0.0.1:8000/**. Всегда открывай его в одном и том же обычном профиле браузера. Команда запуска — только `python3 serve.py` из папки проекта; она по умолчанию использует 127.0.0.1 и порт 8000. Для остановки сервера: Ctrl+C. Если порт занят, вернись к уже запущенному серверу или останови его; не выбирай другой порт ради доступа к старым записям.
Локальный сервер отдаёт файлы с `Cache-Control: no-store`, чтобы браузер не смешивал старый JavaScript с новой разметкой после изменений.

Не запускай двойным щелчком через file://: JavaScript-модули требуют HTTP.

## Подготовка к GitHub Pages

Ничего пока не опубликовано. Для GitHub Pages подготовлен ручной workflow `.github/workflows/pages.yml` — **Publish GitHub Pages (manual)**. Он не запускается при push или pull request: публикацию нужно отдельно запустить через **Run workflow**. До успешных проверок и подготовки статических файлов шаг публикации не выполняется. Токены и платные сервисы для приложения не нужны.

Сайт остаётся статическим HTML/CSS/JS без npm-зависимостей и сборки. `prepare_pages.py` только проверяет локальные ссылки и копирует нужные файлы в пустую папку; ничего не отправляет в сеть и не читает браузерные конспекты. В пакете есть `index.html` в корне, стили, модули, Worker, Onest с лицензией OFL и `.nojekyll`. Относительные пути позволяют открывать приложение как в корне домена, так и по пути `/имя-репозитория/`. Адрес будущего проекта: `https://USER.github.io/REPOSITORY/` (USER и REPOSITORY замени на свои).

Подготовить только статический пакет локально:

```bash
python3 prepare_pages.py --output _site
```

Папка `_site/` не попадает в Git. Если она уже непустая, команда остановится, сохранив все файлы; для следующей проверки выбери другую пустую папку через `--output`.

Подготовить чистые исходники для будущего GitHub-репозитория:

```bash
python3 prepare_pages.py --source --output /tmp/vibenotes-github
```

Эта команда копирует только перечисленные в скрипте файлы приложения, проверок и workflow. Она не копирует `.git`, локальные файлы размещения, JSON-копии заметок или старые шрифты. Рабочая папка и история текущего проекта остаются на месте. `/tmp` — временное место: перед выключением компьютера перенеси подготовленную папку в постоянную папку.

**Шрифты:** в этой копии используется только Onest с лицензией в `dist/fonts/Onest-OFL.txt`. Файлов шрифта FT40 здесь нет; старая история исходного проекта также не включена.

Когда решишь публиковать (эти действия сейчас не выполнялись):

1. Создай на GitHub пустой репозиторий, например `vibenotes`. Для бесплатного GitHub Pages с GitHub Free нужен публичный репозиторий; доступность Pages в приватном репозитории зависит от тарифа.
2. В этой папке уже создан отдельный Git-репозиторий с одним начальным коммитом и веткой `main`. Когда решишь публиковать, добавь адрес своего пустого GitHub-репозитория как `origin` и отправь `main` по инструкциям GitHub. Повторно создавать Git-репозиторий не нужно. Не добавляй резервные JSON-копии и фотографии конспектов в исходники. Один только push не запускает наш workflow публикации.
3. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**. Не выбирай публикацию из корня ветки или `/docs`: рабочие файлы лежат в `dist`, а workflow сам формирует пакет сайта.
4. Во вкладке **Actions** выбери **Publish GitHub Pages (manual)** → **Run workflow** и основную ветку. Это уже запускает публикацию. Проверяются Node-тесты, Python-тесты и целостность пакета; затем загружается только подготовленный статический пакет и выполняется deploy в окружение `github-pages`.
5. После успешного запуска открой адрес из окружения `github-pages`, с HTTPS и завершающим `/`. Не добавляй `/dist/` к адресу сайта. Для обновления кода снова отправь изменения и вручную запусти этот же workflow.

Настройка workflow соответствует [официальной инструкции GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Источник публикации выбирается по [инструкции GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

### Конспекты после публикации

GitHub Pages размещает приложение, но не добавляет регистрацию, серверное хранение и синхронизацию. Записи по-прежнему хранятся в IndexedDB текущего браузера. Новое устройство не получит их автоматически.

Перед переездом на Pages скачай полную резервную копию на прежнем адресе. На опубликованном сайте открой **Настройки → Восстановить из файла**, выбери JSON, подтверди восстановление и дождись «✓ Сохранено». Проверь страницы, штрихи, текст, фото и обложки; обнови страницу, затем полностью закрой и снова открой тот же браузер. Сохрани исходную JSON-копию вне браузера.

Локальный адрес `http://127.0.0.1:8000/` и `https://USER.github.io` имеют разные хранилища. Внутри одного origin `https://USER.github.io` разные проекты `/project-a/` и `/project-b/` используют общее браузерное хранилище: не размещай вторую независимую копию этого приложения на том же origin. Для отдельного набора записей нужен другой origin или профиль браузера. Смена собственного домена тоже меняет origin и требует переноса через JSON. Формат данных version:1 при подготовке к Pages не меняется.

## Данные

Конспекты и фото сохраняются в IndexedDB этого браузера. Сервер получает только запросы статических файлов; приложение не отправляет конспекты на сервер. Данные отдельные для каждого origin (сочетания протокола, домена и порта) и профиля браузера; путь внутри одного домена не создаёт отдельного хранилища. Чтобы перенести записи с опубликованного сайта на localhost, скачай резервную копию JSON и восстанови её на новом адресе. Не очищай данные сайта без копии. Автоматической синхронизации и серверного резервирования нет.

Обычное закрытие браузера сохраняет IndexedDB. `localhost`, другой порт, другой профиль, другой браузер и опубликованный сайт имеют отдельные хранилища. В приватном режиме данные могут исчезать после закрытия окна. Очистка данных сайта и автоматическое удаление данных при выходе тоже удаляют конспекты. Git-коммиты содержат код приложения, а конспекты — в браузере: Git не является их резервной копией.

При ошибке открытия, чтения или проверки сохранённого документа приложение показывает постоянное сообщение и не открывает пустую начальную тетрадь. Сохранённый ключ `workspace/state` не изменяется. Если исходный объект удалось прочитать, его можно скачать кнопкой резервной копии даже при ошибке проверки формата. «Повторить открытие» перечитывает данные; очищать браузер для этого не нужно. Только действительно отсутствующая запись в новом хранилище создаёт первую пустую тетрадь.

Одна вкладка держит блокировку записи через Web Locks; вторая не открывает устаревшую редактируемую копию. Чтобы продолжить в другом окне, закрой первую вкладку и нажми «Повторить открытие». Нужен современный браузер с Web Locks: локально по указанному адресу или на опубликованном сайте с HTTPS; без этой защиты редактор не запускается. После обновления с прежней версии закрой старые вкладки приложения, чтобы не оставлять открытый старый код без защиты.

В «Настройки» → «Закрепить хранение в браузере» можно запросить постоянное хранение, защищающее от автоматического вытеснения данных. Решение принимает браузер; отказ отображается явно. Оно не защищает от ручной очистки, удаления профиля или поломки диска, поэтому JSON-копия нужна отдельно.

Полная резервная копия: «Скачать резервную копию» выгружает все тетради, вложенные и пустые папки, документы, страницы, текст, штрихи с нажимом, встроенные фото, обложки и оформление листов в один JSON version:1. «Настройки» → «Восстановить из файла» сначала проверяет JSON, затем спрашивает подтверждение замены; отмена и ошибочный файл не меняют текущие записи. Дополнительного ограничения 150 МБ, которое мешало бы восстановить собственный большой экспорт, больше нет; остаются ограничения формата и доступной памяти браузера. После восстановления дождись «✓ Сохранено». Настройки темы и основного цвета интерфейса хранятся отдельно от конспектов. В «Настройки» → «Основной цвет» доступна палитра любого цвета с предпросмотром. Фон, панели и разделители в светлой и тёмной теме используют мягкие оттенки выбранного цвета, без фиксированной розовой подложки. «Сохранить» запоминает выбор, отмена возвращает прежний цвет; «Вернуть розовый» выбирает исходный акцент. Цвета записей, бумаги и пользовательских обложек не меняются.

Проверка после полного закрытия браузера:

1. Открой постоянный адрес в обычном профиле. Добавь короткую заметку, штрих и фото; запомни название документа и количество страниц.
2. Дождись «✓ Сохранено» и скачай полную резервную копию JSON в папку вне профиля браузера.
3. Полностью закрой все окна браузера. Не очищай его данные. Если сервер остановлен, снова запусти `python3 serve.py` из папки проекта.
4. Запусти тот же браузер с тем же профилем и открой http://127.0.0.1:8000/.
5. Выбери прежнюю тетрадь и документ: проверь текст, штрих, фото и страницы. Приложение всегда начинает с главного экрана — это не означает, что конспекты исчезли.
6. Если данные не показались, проверь адрес и профиль. При сообщении об ошибке не очищай хранилище: скачай доступную копию и сохрани текст ошибки.

Фото при добавлении уменьшаются до 2000 px по длинной стороне, GIF импортируется как статичное изображение. История отмены хранится до 60 действий на страницу для текущего и десяти недавно открытых листов. Ctrl+Z отменяет действие, Ctrl+Shift+Z и Ctrl+Y возвращают его; сочетания работают и в русской раскладке, в том числе после выбора бумаги и толщины пера. В текстовых полях действует обычная отмена ввода. Перезагрузка и восстановление резервной копии сбрасывают историю. Бумага не входит в историю отмены. Ластик удаляет штрих целиком. Рисование ограничено размером страницы. В режиме лассо (V) обведи от руки штрихи, фото или текст целиком. Можно выделить несколько объектов и перетаскивать их вместе за выделенную область. Одиночный щелчок объект не выделяет. Правая кнопка на странице открывает меню: копировать, вставить, дублировать, удалить, изменить порядок наложения. Меню не занимает место на странице и закрывается после действия или нажатия снаружи. Ctrl+C / Ctrl+V копируют и вставляют внутри приложения, в том числе между страницами; Ctrl+D создаёт копию выделенной группы, Delete удаляет группу, Esc снимает выделение. Буфер копирования хранится в памяти до перезагрузки. Один выделенный текст редактируется двойным щелчком или пунктом «Изменить текст» в меню. Фигуры, рукописные штрихи и фото можно растягивать за углы и стороны рамки выделения: ширина и высота меняются независимо, толщина линий сохраняется. Для фото удерживай Shift при растягивании угла или стороны: ширина и высота изменятся пропорционально, без искажения. У группы из нескольких фото Shift также сохраняет пропорции. Отпусти Shift, чтобы снова менять размеры свободно. Кнопка «Очистить страницу…» удаляет все штрихи, фото и текст текущей страницы после подтверждения, сохраняя название и бумагу. Очистку и действия с объектами можно отменить, пока страница остаётся в недавней истории. Нажим зависит от передачи Pointer Events драйвером и браузером; есть переключатель постоянной толщины.

Интерфейс и стандартные обложки оформлены в розовой палитре. Интерфейс использует Onest с кириллицей. Название сайта и заголовок библиотеки имеют одинаковую умеренную жирность 650. Onest хранится локально в `dist/fonts` с лицензией и работает без интернета. Выбранные пользователем цвета обложек, загруженные картинки и уже написанные штрихи не перекрашиваются. Инструменты рисования, цвет, толщина, нажим, выбор бумаги, очистка страницы, фото и отмена собраны в одной верхней панели. Между лассо и пером есть кнопка текущей толщины («3 px»). Нажатие открывает бегунок от 1 до 24 px; число на кнопке обновляется сразу. Щелчок снаружи, Escape или повторное нажатие закрывает шкалу. Все элементы стоят в одну строку; в узком окне панель прокручивается по горизонтали.

Внизу боковой панели остаются только «Настройки» и «Скачать резервную копию». Восстановление из файла доступно внутри настроек. Кнопка «Настройки» открывает выбор светлой и тёмной темы с предпросмотром. «Сохранить» запоминает тему в этом браузере (`localStorage`, отдельно от документов); отмена, Escape и щелчок снаружи возвращают прежнюю тему. Тёмная тема меняет панели, меню и окна. Тема интерфейса не меняет выбранный цвет бумаги, цвета записей и обложек.

## Тетради, папки и документы

На боковой панели есть одна кнопка «Добавить тетрадь» и список всех тетрадей. Нажатие на закрытую папку раскрывает её и показывает содержимое; повторное нажатие сворачивает список, не закрывая открытый документ. Те же действия доступны через Enter на заголовке папки. Правая кнопка мыши по тетради или вложенной папке открывает меню для добавления в неё папки либо документа-холста. При создании документа в одном окне задаются название, разметка (клетка, точка, линейка или без разметки) и цвет холста (белый, желтоватый или чёрный). Кнопка «Создать» или Enter в названии создаёт документ с выбранным первым листом. Отмена не создаёт документ. При создании тетради и папки Enter также сохраняет название. При запуске главный экран показывает все тетради, без открытого холста; тетради слева свёрнуты. Возврат к «Моим тетрадям» также сворачивает дерево. Нажатие на папку в центре или слева открывает её содержимое в центре: вложенные папки и документы. Нажатие на документ открывает холст со всеми инструментами. Кнопка «Мои тетради» возвращает к главному экрану, «Назад» — к родительской папке. Пустая папка предлагает добавить папку или документ. Правая кнопка мыши работает и на карточках главного экрана. Чтобы изменить название тетради, папки или документа, нажми правой кнопкой мыши по названию и выбери «Переименовать…», введи новое название и нажми Enter или «Готово». Двойной щелчок по названию также открывает переименование.

В меню по правой кнопке у папки или документа есть «Изменить обложку…»: палитра, свой цвет, картинка PNG/JPEG/WebP (до 25 МБ) и возврат стандартного вида. Предпросмотр не меняет записи до нажатия «Сохранить»; «Отмена» и щелчок снаружи сохраняют прежнюю обложку. У документов пункт «Цвет корешка…» открывает такую же палитру для левой боковой полоски: предпросмотр, свой цвет, сохранение и возврат розового цвета. Обложка и картинка при этом сохраняются; сброс основной обложки тоже сохраняет выбранный цвет корешка. Необязательное поле `cover.spineColor` входит в JSON version:1, старые копии без него открываются как прежде. У папок цвет выступа независим от передней части и картинки. По умолчанию он розовый; пункт «Цвет выступа…» в меню правой кнопки открывает отдельную палитру, выбор любого цвета и возврат стандартного оттенка. Нажатие на поле цвета открывает системную палитру браузера. Цвет применяется по «Сохранить», отмена не меняет обложку. Необязательное поле `cover.tabColor` сохраняется в том же JSON version:1; старые копии без этого поля используют прежний розовый выступ. Из изображения готовой папки автоматически выбирается широкая прямоугольная часть без её собственного выступа; обычные фотографии и текстуры используются целиком после удаления внешних полей. Меняется только передняя часть обложки. Размер папки и сохранённый исходник остаются прежними. Картинка уменьшается до 1000 px по длинной стороне и встраивается в данные; без сервера и внешних ссылок. Необязательное поле `cover` в папках и документах сохраняется в IndexedDB и JSON version:1. Старые данные без `cover` открываются со стандартными обложками и не переписывают содержимое страниц.

Щелчок вне окна закрывает его так же, как «Отмена»; нажатия внутри окна его не закрывают. Меню по правой кнопке мыши у папки или документа также позволяет удалить его после подтверждения. Папка удаляется со всеми вложенными папками и документами. Удаление не входит в отмену: заранее скачай JSON, если нужна возможность восстановления. Если удалены все документы, создаётся новый пустой документ для продолжения работы.

Документ открывается нажатием на его строку. Верхняя строка показывает путь к открытому документу: тетрадь, вложенные папки и название документа, затем отдельно номер текущего листа. Путь обновляется при открытии другого документа и переименовании. Он содержит такие же редактируемые холсты с пером, фигурами, текстом и фото, как раньше; внутри документа страницы идут непрерывной лентой. Выбор папки открывает просмотр её содержимого; записи открытого ранее документа сохраняются. Зелёная подсветка слева отмечает только текущий объект: папку при просмотре её содержимого либо открытый документ на холсте. Номера страниц остаются автоматическими.

Старые тетради автоматически получают папку с прежним названием; все их страницы сохраняются в одном документе. Миграция добавляет только метаданные `folders` и `books[].folderId`, сохраняет version:1, идентификаторы страниц, даты, штрихи и встроенные фото. Старые JSON без папок по-прежнему импортируются. Worker, резервное сохранение и экспорт JSON включают всю структуру, в том числе пустые папки.

Удаление страницы доступно через «⋯» в верхней панели → «Удалить страницу…»; отдельной кнопки на панели нет. Удаляется только текущий лист и только после подтверждения; затем открывается соседний. Если удаляется последний лист документа, остаётся новая пустая страница. Это действие не входит в отмену штрихов: восстановление удалённого листа возможно из заранее сохранённого JSON.

На холсте рядом с типом бумаги есть «Цвет листа»: белый, желтоватый или чёрный. Цвет относится к текущему листу, не зависит от темы интерфейса и сохраняется в IndexedDB, JSON и PNG. Разметка на чёрном фоне становится светлее; цвет существующих штрихов и фото не меняется. Для письма на тёмном листе в палитре добавлен белый цвет пера. Старые копии version:1 без необязательного поля `pages[].paperColor` открываются с прежней белой бумагой. Дублирование сохраняет цвет. «Добавить страницу» создаёт пустой лист с разметкой и цветом текущей страницы. Если изменить оформление текущего листа, следующие добавленные страницы наследуют его; существующие страницы не меняются.

## Непрерывные страницы

Все страницы открытого документа идут сверху вниз в одной ленте. Прокручивай её колесом, полосой прокрутки или инструментом «Рука». Переключать страницы в боковой панели больше не нужно. Под последним листом есть кнопка «＋ Добавить страницу», которая добавляет лист в конец. Старые страницы остаются на своих местах.

Можно сразу начать писать на любом видимом листе. Верхняя строка навигации и подпись над листом показывают его порядковый номер: «Страница 1», «Страница 2» и так далее. Менять название страницы нельзя. При добавлении, дублировании или удалении номера обновляются автоматически. Выбор бумаги, выделение, очистка, вставка фото и экспорт PNG относятся к активной странице. При прокрутке активной становится наиболее видимая страница, при письме — лист под пером. JSON по-прежнему содержит все тетради, страницы и встроенные изображения.

Два рабочих холста переиспользуются между страницами. Соседние листы получают отдельные изображения только рядом с видимой областью; при удалении от них эти холсты освобождаются. Длинная тетрадь не создаёт полноразмерные холсты сразу для всех листов. Формат сохранённых данных остаётся version:1.

В изолированном Chrome проверена тетрадь из 40 страниц с фото: письмо сразу на соседнем листе, независимая отмена/повтор, масштабирование под курсором, прокрутка, добавление, дублирование и удаление, названия и бумага, полный экспорт JSON и сохранение после перезагрузки.

## Фото из буфера обмена

Скопируй изображение или снимок экрана, вернись в vibenotes и нажми Ctrl+V вне текстового поля. Наведи курсор на нужное место листа: фото вставится туда, автоматически выделится и будет доступно для перемещения, растягивания, копирования и удаления. Это работает с прокруткой и любым масштабом, в том числе на соседнем видимом листе. Скопированные объекты тетради тоже вставляются у курсора, сохраняя взаимное расположение. Ctrl+V работает и сразу после выбора бумаги, изменения толщины или переключения нажима; щёлкать по листу перед вставкой не требуется. У края вставка сдвигается внутрь листа, чтобы поместиться целиком. Если курсор ещё не был на листе, вставка появляется в видимой части текущей страницы. Если буфер содержит несколько изображений, они добавляются вместе; Ctrl+Z отменяет всю вставку одним шагом.

Вставка использует те же ограничения, что и кнопка «Фото»: до 25 МБ на изображение и уменьшение до 2000 px по длинной стороне. Изображения встраиваются в документ и резервную копию JSON. В полях редактирования текста Ctrl+V сохраняет обычное поведение. Буфер должен содержать само изображение, а не только ссылку на него. Копирование и вставка объектов приложения через Ctrl+C / Ctrl+V также сохраняются.

## Фигуры из меню

Нажми значок круга с квадратом в верхней панели и выбери круг, овал, квадрат, прямоугольник, трапецию, прямоугольную трапецию, параллелограмм или ромб. Проведи пером или мышью по странице, чтобы задать размер фигуры. Круги и квадраты при создании сохраняют равные размеры по обеим осям. После отпускания фигура автоматически выделится. При включённом нажиме новые фигуры получают среднюю толщину недавнего письма пером на этой странице; среднее учитывает длину линии, а не количество событий планшета. При выключенном нажиме письмо и фигуры имеют точно выбранную толщину: например, 3 px. Уже сохранённые штрихи и их нажим не переписываются.

Перетаскивай выделенную область для перемещения. Восемь маркеров на углах и серединах сторон рамки позволяют независимо изменять ширину и высоту. Круг можно растянуть в овал, а квадрат — в прямоугольник. Позже фигуру можно снова обвести лассо и продолжить редактирование. Группы штрихов и фото тоже можно растягивать вместе. Фигуры и группы рукописных штрихов можно вращать на любой угол: перетаскивай круглую ручку у рамки вокруг её центра. Shift задаёт шаг 15°. В меню по правой кнопке доступны повороты на 90° влево и вправо, а также отражения слева направо и сверху вниз. Нажим и толщина линий при этом сохраняются. Эти преобразования применяются к фигурам и штрихам; для фото и печатного текста они недоступны. Ctrl+Z отменяет создание, растягивание, поворот и отражение; копирование и резервные копии работают как для обычных штрихов. Прерванное создание не добавляет фигуру на страницу.

## Ровные геометрические фигуры

Выбери «Перо», нарисуй фигуру одним штрихом и в конце задержи перо на месте примерно на 0,45 секунды, не отрывая от планшета. Линия, круг, овал, треугольник или прямоугольник выровняются. Близкие к квадрату прямоугольники становятся квадратами. Для замкнутых фигур вернись близко к началу контура: небольшой разрыв допустим. Допускаются неровные и скруглённые углы, выгнутые стороны, короткий заход за начало контура и небольшой хвостик при замыкании. Можно рисовать наклонные фигуры.

Подними перо, чтобы сохранить результат. Чтобы продолжить свободный рисунок, сдвинь перо дальше: исходный штрих вернётся. Если просто нарисовать и сразу поднять перо, выравнивание не сработает. Маркер не выравнивается. Незнакомая форма остаётся свободным штрихом. Ctrl+Z отменяет добавление фигуры. Фигура хранится обычным штрихом в формате version:1 и доступна для выделения, перемещения, копирования, удаления, экспорта и импорта. Распознавание проверено автоматически; удержание и нажим на настоящем планшете нужно проверить отдельно.

## Удаление росчерком

В режиме «Перо» зачеркни ненужное одним непрерывным росчерком: несколькими движениями туда-обратно, зигзагом или волнистой линией с несколькими высокими изгибами. Подходят горизонтальные, вертикальные и наклонные жесты. Нужно хотя бы три заметные смены направления; мелкая дрожь пера не учитывается. Ограничения по скорости нет. Функция включена постоянно без надписей и переключателей на панели.

После отпускания пера удаляются объекты в прямоугольной области росчерка: фото, текстовые блоки и рукописные штрихи, включая отдельные штрихи букв. Штрих, проходящий через эту область, удаляется целиком. Сам росчерк тоже исчезает. Ctrl+Z возвращает удалённое одним шагом; история отмены сохраняется для недавно открытых страниц.

Обычные крестики больше не запускают удаление. Росчерк на пустом месте остаётся рисунком. Маркер и прерванные жесты не удаляют объекты. Рисунок, похожий на зачёркивание поверх существующих записей, тоже может быть распознан как удаление. Автоматические тесты проверяют формы жестов и отмену; работу на настоящем планшете нужно проверить отдельно.

## Производительность и сохранение

Во время письма текущий штрих рисуется на отдельном прозрачном холсте. Уже написанная страница не перерисовывается на каждом событии пера. События объединяются в кадры, но все точки и значения нажима остаются в документе. Завершённые штрихи остаются редактируемыми, а история отмены переиспользует неизменённые данные вместо полного копирования каждой страницы на каждом шаге.

Сохранение объединяет близкие изменения и передаёт изменённые объекты фоновому Worker. Запись IndexedDB выполняется там, не блокируя письмо. Если Worker недоступен, работает резервный последовательный режим сохранения без растущей очереди снимков. Формат данных не изменён: полный документ version:1 по-прежнему хранится в `workspace/state`, а JSON включает все страницы и встроенные фото. Для старых записей и JSON автоматически добавляется структура папок, описанная выше; содержимое страниц не переписывается.

«✓ Сохранено» появляется только после `transaction.oncomplete` последнего изменения в IndexedDB. Для записи задано `durability: strict`, в том числе в Worker. Ошибка не прячется за кратким уведомлением: остаются статус «Не сохранено», объяснение и кнопка повторной записи; текущие записи доступны для JSON-экспорта. Worker, который не запустился за 5 секунд, заменяется последовательной записью полного документа в основном потоке. При ошибке чтения этот резервный режим не создаёт начальные данные. Пока есть несохранённые изменения, закрытие вкладки вызывает предупреждение. При скрытии вкладки приложение запрашивает немедленное сохранение.

В изолированном тестовом Chrome на странице с 1200 штрихами и 96000 точками максимальная длительность обработчика синтетического события пера снизилась с 593 до 1,2 мс. При добавлении пяти штрихов количество операций рисования основного холста уменьшилось с 6638200 до 60. Проверены запись в IndexedDB, импорт двух страниц с фото, отмена/повтор и совпадение изображения страницы с PNG. Это измерение на тестовых данных, а не проверка задержки или нажима реального планшета.

## Файлы

- `serve.py`: локальный HTTP-сервер без кэширования файлов приложения
- `prepare_pages.py`: подготовка статического пакета или чистых исходников для GitHub
- `.github/workflows/pages.yml`: ручная проверка и публикация на GitHub Pages (без автоматического запуска по push)
- `dist/index.html`: интерфейс
- `dist/style.css`: стили
- `dist/app.js`: холст, инструменты, IndexedDB, импорт и экспорт
- `dist/core.mjs`: формат документа, геометрия и проверка резервных копий
- `dist/shapes.mjs`: распознавание и выравнивание геометрических фигур
- `dist/ink.mjs`: рисование новых точек пера на отдельном слое
- `dist/page-stack.mjs`: непрерывная лента страниц и подгрузка соседних холстов
- `dist/library.mjs`: миграция старых тетрадей и пути вложенных папок
- `dist/persistence.mjs`: изменения документа и снимки для сохранения
- `dist/storage-worker.mjs`: фоновая запись IndexedDB
- `tests/core.test.mjs`: проверки геометрии и резервных копий

Запуск проверок:

```bash
node --test tests/core.test.mjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

Браузерная проверка основных инструментов (нужны Chrome и Node.js 22+ с WebSocket; сервер должен быть запущен):

```bash
node tests/browser-smoke.mjs http://127.0.0.1:8000/
node tests/storage-browser.mjs http://127.0.0.1:8000/
```

Сценарий сам запускает отдельный временный профиль Chrome и проверяет только созданные им тестовые записи. Он проверяет защиту от старого файла в кэше, выбор бумаги, письмо, маркер, ластик, фигуры, лассо, перемещение, поворот, копирование, вставку фото и текста, очистку с отменой, непрерывные страницы, JSON с фото и сохранение после перезагрузки. Отдельно проверяются миграция старых тетрадей, вложенные и пустые папки, новые документы, переименование, удаление страницы с подтверждением и сохранение дерева в JSON. Отдельный `storage-browser.mjs` использует собственный временный профиль: сверяет полный JSON с записью IndexedDB после обновления и полного завершения/перезапуска процесса Chrome, проверяет блокировку второй вкладки, имитирует отказ записи и чтения. Пользовательский профиль не читается и не меняется. Проверка системного буфера обмена и нажима реального планшета остаётся ручной.

После изменения файлов статического пакета для опубликованной версии нужно обновлять параметр `?v=` у CSS, входного JavaScript, импортов модулей и Worker. При локальной работе используйте `serve.py`, чтобы изменения не сохранялись в HTTP-кэше.

Проверены синтаксис, схема документа, геометрия попадания ластика и структура статического пакета. Браузерная проверка актуальной версии описана выше. Реальное рисование и давление нужно проверить на своём графическом планшете.
